# 場域字串清單（唯一真實來源）

`school` 字串把整個系統的「學生、成績、場域、老師」串在一起。Unity、前端、後端
三方**必須用完全相同的字串**，差一個字（全形半形、空白、破折號變體）就永遠對不
起來，而且**不會報錯**、只會查出空資料。

**廠商把命名交給後端決定。定案如下，這份是唯一真實來源。**

## 正式清單（8 個場域）

| `school`（程式用，複製貼上要一模一樣） | 顯示名稱（`displayName`，可調整） | 排序 |
|---|---|---|
| `KMU` | 高雄醫學大學 | 0 |
| `NTHU-01` | 清華大學（第一場） | 1 |
| `NTHU-02` | 清華大學（第二場） | 2 |
| `NTHU-03` | 清華大學（第三場） | 3 |
| `NTHU-04` | 清華大學（第四場） | 4 |
| `NTHU-05` | 清華大學（第五場） | 5 |
| `NTHU-06` | 清華大學（第六場） | 6 |
| `NTHU-07` | 清華大學（第七場） | 7 |

- `school` 值：**大寫英數字 + 半形連字號 `-`（U+002D）**。沒有空白、沒有中文、沒有其他符號。
- `KMU` = 高雄醫學大學（1 場）。`NTHU-01`…`NTHU-07` = 清華大學（7 場）。
- 已寫入正式庫 `AttentionLessonPlan.school` 與測試庫 `AttentionLessonPlan_test.school`。

## 各方怎麼用

| 誰 | 怎麼用 |
|---|---|
| **Unity** | 每個場域的 build 把 `data.school` 送**上表第一欄的字串**（例 `"NTHU-03"`）。寫死前請逐字對照本表 |
| **前端** | 不要寫死。呼叫 `GET /api/schools` 取得清單，顯示 `displayName`，把 `school` 原樣帶回後續 API |
| **後端** | `seed_directory.py` 的 `SCHOOLS` 常數即為本表。改字串 = 改常數 + 重跑 |

## 待廠商補（不影響開工）

- **顯示名稱**：「（第一場）」等是暫定的。廠商知道 7 個清大場次實際怎麼區分（地點？梯次？）
  後，改 `display_name` 即可 —— 這**不是** join key，`UPDATE school SET display_name=...`
  一行就好，不影響任何既有資料。
- **16 位老師的實際姓名**：目前是佔位（吳老師、林老師…）。廠商給實際名單後，清 `teacher`
  表重灌。`teacher_id` 會變，但目前沒有任何資料參照 `teacher_id`，無妨。

## 為什麼用代碼不用中文

避免全形／半形、空白、破折號變體（`-` vs `–` vs `—` vs `－`）造成的隱性不一致 ——
這種錯不會報錯，只會讓資料默默對不起來。代碼放路徑參數（`/api/schools/NTHU-03/teachers`）
也乾淨、不用 URL encode。中文一律放 `display_name`。
