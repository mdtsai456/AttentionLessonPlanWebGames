## 4. 怎麼啟動 Demo 畫面

開一個 PowerShell 視窗，`cd` 到專案資料夾：

```powershell
git checkout integration          # 切到完整版分支
uv run uvicorn main:app --port 5001
```

看到 `Application startup complete` 後，瀏覽器開：

| 網址 | 是什麼 |
|---|---|
| `http://127.0.0.1:5001/demo` | Demo 畫面 |
| `http://127.0.0.1:5001/docs` | API 文件（可逐一點端點試） |

**Demo 操作**：老師端 → 選場域（高雄醫學大學）→ 選老師（吳老師）→ 點學生 → 看報告。
或直接開 `http://127.0.0.1:5001/demo?school=KMU&student=G1_S01` 跳到報告頁。

關掉 PowerShell 視窗 = 停掉伺服器。

### 假資料被清掉時重灌

```powershell
uv run python seed.py
uv run python seed_directory.py
```

## 5. 怎麼跑測試

```powershell
uv run pytest -q
```

連遠端資料庫，一輪約 2–3 分鐘。**切換分支後**（例如從 main 切到功能分支）第一次跑
可能要先重建 `_test`，因為 `schema.sql` 用 `CREATE TABLE IF NOT EXISTS`，不會自動補
新欄位：

```powershell
uv run python -c "import pymysql; c=pymysql.connect(host='43.163.233.40',port=31497,user='root',password='<看 .env>'); cur=c.cursor(); cur.execute('DROP DATABASE IF EXISTS AttentionLessonPlan_test'); cur.execute('CREATE DATABASE AttentionLessonPlan_test CHARACTER SET utf8mb4'); c.commit()"
```

## 6. 還沒做的事

### 6-1. 推到廠商 repo `github.com/mdtsai456/AttentionLessonPlanWebGames`

- 你說要先確認沒問題再推 → 現在測試都綠了，可以推了。
- 推之前要先看那個 repo 的結構（可能只是 Unity 的、也可能是整包），決定後端 code
  放哪個資料夾／分支。
- 需要：那個 repo 的**寫入權限**（廠商加你當 collaborator，或你 fork）。

### 6-2. 正式庫上線（`AttentionLessonPlan`）

**這是什麼**：現在正式網站（Zeabur 上那個）背後的資料庫 `AttentionLessonPlan` 是
**空的 —— 沒有任何表格**。所以正式網站現在任何查詢都會失敗。要讓它能用，得在這個
資料庫裡：

1. **建表**：把 9 張表建起來（student、assessment_result〔含新的 mode/pair_id〕、
   5 張遊戲結果表、school、teacher）。—— 這個**我可以現在用 root 幫你跑**，
   資料庫是空的，零風險。跟你說一聲就做。
2. **灌場域／老師參照資料**：`school`、`teacher` 兩張表要有 8 個場域 + 16 位老師。
   —— **卡在廠商的 8 個正式場域字串**。字串來了之後，改一下 `seed_directory.py` 的
   常數、用 root 跑 `python seed_directory.py --prod` 即可。
3. **帳號權限**：目前只有 root。理想上正式網站應該用權限受限的帳號（唯讀帳號查詢、
   限制寫入帳號給 Unity），見 `docs/adr/0001`。但這是「要不要現在做」的決定 ——
   先用 root 也能動，只是安全性差。**你要決定**：跟廠商要求建 `app_ro` / `game_writer`
   兩個帳號，還是先用 root 上線、之後再收緊。

**你現在需要做的**：(a) 跟我說要不要現在建表；(b) 跟廠商要 8 個場域字串；
(c) 決定帳號權限那件事。

### 6-3. Zeabur 環境變數

**這是什麼**：正式網站部署在 Zeabur。Zeabur 上有一組「環境變數」設定，是網站跑起來
時用的（資料庫在哪、密碼是什麼、CORS 放行誰）。**這組設定跟你本機的 `.env` 是分開
的兩份。** 目前 Zeabur 上那組可能還寫著**舊的資料庫位址**（舊 port `31913`，廠商這次
給的是 `31497`）—— 如果是，正式網站現在根本連不到資料庫。

要更新的環境變數：

| 變數 | 改成 |
|---|---|
| `DB_HOST` | `43.163.233.40` |
| `DB_PORT` | `31497`（從 `31913` 改） |
| `DB_USER` / `DB_PASSWORD` | 正式庫查詢帳號（root 或 `app_ro`，看 6-2 第 3 點的決定） |
| `DB_WRITE_USER` / `DB_WRITE_PASSWORD` | 正式庫寫入帳號（root 或 `game_writer`） |
| `DB_NAME` | `AttentionLessonPlan` |
| `CORS_ALLOW_ORIGINS` | 前端正式網址（前端組員部署後給你）；還沒有的話先留空或填 `*` |

**你現在需要做的**：確認你有沒有 Zeabur 專案的存取權。沒有的話跟廠商要。有的話，
等 6-2 做完、前端網址出來，我可以列一份精確的「要在 Zeabur 填什麼」清單給你照填。

### 6-4. 跟 Unity 組員對欄位

已經產好一份交接文件：**`docs/unity-integration-guide.md`**，可以直接轉給那六位
（3 款遊戲 × 單人/雙人各一位）。重點：

- 單人版負責人：**不用改**。
- 雙人版負責人：`data` 裡多送 `mode: "double"` 和 `pairId`（一場雙人局一個 GUID、
  兩位學生共用）。
- 六個人都要確認送的 `data.school` 字串跟正式場域清單一致（清單還沒定案，先用佔位碼）。
