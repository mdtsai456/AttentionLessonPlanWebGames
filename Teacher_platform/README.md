# Teacher_platform

老師看學生進度的頁面。`Home/` 以老師身份登入後會進到這裡。

## 做什麼

1. 確認 session 裡是老師 token。不是老師就回 `Home/`。
2. 顯示老師姓名與場域，並拉這位老師名下的學生名單。
3. 選一位學生，再選第 1～24 天。
4. 展開當天五個遊戲的進度與場次明細。

五個遊戲與 `Select/` 相同：賽道攔截、瓢蟲追擊令、漂浮泡泡、勇闖迷宮、指令出擊。遊戲清單與進度算法都來自 `shared/api.js` 的 `GAMES`、`dayProgress`：`stage` 在 3 以內是 50%，其後是 100%。

名單與場次都從後端來。老師只能看自己場域的學生，範圍由後端限制。名單讀不到時，下拉選單與提示卡顯示「學生名單讀取失敗」，和沒有學生分開。

換學生時會先清掉上一位的場次，等這位學生的成績回來才能選天；較晚回來的舊學生回應會丟掉。讀取失敗時天數按鈕維持停用，並顯示讀取失敗的提示。

後端的時間字串（`lastPlayedAt`、`startTime`）是 UTC、不帶時區，畫面上的「最後評測時間」與「開始時間」一律換成台灣時間（UTC+8）再顯示，不跟著裝置的時區設定，格式仍是 `YYYY-MM-DD HH:MM:SS`。

### 一個課次分兩次玩完

學生在一個課次只打完前 3 關就離開時，報表有一列 `stage` 3；下次進同一款、同一模式的遊戲會從第 4 關開始，打完另送一列 `stage` 6。這一列只含第 4～6 關，`levelAccuracy` 只有 3 個值。每個遊戲的卡片會把這兩列合併成一場顯示：

- **認出後半**：`stage` 是 6，而且 `levelAccuracy` 剛好 3 個值。打完整局的 `stage` 6 一定有 6 個值。
- **配對**：後半配同模式、`startTime` 比它早的最後一筆 `stage` 3（前半玩了兩次時取較晚的那次）。單人、雙人各有一組時，取後半較晚的那一組。
- **不合併**：同一個課次有一列完整 6 關的成績時，卡片顯示完整那一列。配不到前半的後半列照舊和其他列比關卡高低，同樣是第 6 關時完整的一列優先；它被選中時，3 個各關正確率顯示在第 4～6 關，第 1～3 關顯示「尚無各關紀錄」。
- **合併算法**：
  - 答對、答錯、題數、遊玩時間、專心時間：兩列相加。
  - 正確率：合計答對 ÷ 合計題數。指令出擊沒有 `questionCount`，題數用答對加答錯。
  - 平均反應時間：依兩列題數加權平均。
  - 瓢蟲追擊令的準心對準時長比：依兩列遊玩時間加權平均。
  - 各關正確率：前半的 3 個值接後半的 3 個值。前半沒有各關紀錄時，第 1～3 關顯示「尚無各關紀錄」。
- **明細表**照舊一場一列，後半那一列的關卡欄顯示「6（第 4～6 關）」。
- 進度條不用合併：後半那一列是 `stage` 6，本來就是 100%。學生選單的「已測 N 場」用後端的 `sessionCount`，這樣的一個課次算 2 場。

## 檔案

| 檔案 | 用途 |
| --- | --- |
| `index.html` | 後台畫面 |
| `app.js` | 讀名單、選天、畫進度與明細、登出 |
| `style.css` | 版面 |
| `img/` | 圖 |

頁首的登入守門是 `shared/require-student.js`，這頁要求 `data-role="teacher"`。登出會清掉 session 並回到 `Home/`。
